11. FINANCIAL NUMBER RULE
======================================================================

THIS RULE IS CRITICAL.

Never use JavaScript floating point Number for:

balances
prices
quantities
fees
settlement
rewards
financial calculations

Use PostgreSQL:

NUMERIC(36,18)

where suitable.

Use decimal-safe arithmetic library if calculations must occur
inside Node.js.

Financial values coming from APIs should generally be strings.

Example:

{
  "amount": "1.250000000000000000",
  "price": "67452.12000000"
}

Never silently round financial values.

Create centralized:

decimal parser
precision validator
asset precision rules
market price precision
quantity precision
rounding rules

12. DOUBLE-ENTRY LEDGER
======================================================================

Do NOT build a cryptocurrency exchange where:

users.balance

is the source of truth.

Implement an immutable double-entry accounting ledger.

Tables:

ledger_accounts

ledger_transactions

ledger_entries


Ledger transaction types:

DEPOSIT
WITHDRAWAL
TRADE
FEE
STAKING_REWARD
REFERRAL_REWARD
ADJUSTMENT
REVERSAL


Create accounts such as:

USER_AVAILABLE
USER_LOCKED

EXCHANGE_CLEARING
WITHDRAWAL_CLEARING
FEE_REVENUE
SYSTEM_ACCOUNT


Every financial transaction must balance.

Never directly manipulate balances without ledger records.

Historical ledger entries must be immutable.

Do NOT:

UPDATE ledger_entries ...

Do NOT:

DELETE ledger_entries ...

Corrections must create:

REVERSAL

or:

ADJUSTMENT

transactions.

ledger calculated balance

14. DATABASE TRANSACTIONS
======================================================================

   // validate balance

   // create domain transaction

   // update materialized balances

All operations either succeed or fail together.

Never allow partial settlement.
